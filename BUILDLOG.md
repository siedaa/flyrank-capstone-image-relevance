# Build Log — AI Usage

## Where AI helped

### Schema design and ORM models
AI (opencode + Claude as design guide) generated the initial `ImageTag`
Pydantic schema, the SQLAlchemy `Image`/`Post`/`Suggestion`/`Approval`
models, and the Alembic migration. The schema shape (subject, category,
attributes, caption, confidence) was iterated on during conversation to
match what Gemini actually returns from its structured output mode.

### Batch ingestion pipeline scaffolding
The retry logic, rate-limit detection, daily quota bail-out, cost tracking,
and resumability check were all built incrementally through conversation.
AI wrote the initial `run_batch_ingestion()` loop, the `_is_rate_limit()`
and `_is_daily_quota()` helpers, and the `_parse_retry_delay()` regex
extractor. The pacing delay, exponential backoff, and retry buffer
constants were tuned through trial runs.

### Vision service
`tag_image()` with MIME type detection, `include_usage` flag, and the
structured output schema config were generated by AI and refined through
testing against the actual image dataset.

## Where AI got it wrong

### Model name was outdated
AI initially set `GEMINI_MODEL = "gemini-2.5-flash-lite"`. When we ran
the ingestion, Gemini returned a 404 saying the model was no longer
available and pointed to `gemini-3.5-flash-lite`. This had to be manually
corrected — the AI didn't know the model had been deprecated.

### RATES dict KeyError
After changing the model name, the `RATES` dict didn't have an entry for
`gemini-3.5-flash-lite`, causing a `KeyError` crash on the first run. The
fix (adding the entry + making `_calculate_cost()` defensive with `.get()`)
was applied manually after the crash.

### pytest auto-collected a debug script
`scripts/test_confidence_range.py` was accidentally picked up by pytest
as a test file. Fixed by adding `__test__ = False` at the top of the
script. The script is a standalone debug tool, not a test.

## What I (the developer) changed or caught

### Mislabeled cat photo in the fox folder
During dataset preparation, one image in the `fox/` folder was actually a
cat. I visually inspected the dataset myself and moved/replaced it rather
than trusting the AI's file organization blindly.

### 3 husky/wolf-dog photos mislabeled as wolves
After the full ingestion run, I reviewed the wolf entries in the database
and found that `wolf_01.jpg`, `wolf_07.jpg`, and `wolf_10.jpg` had been
identified as "Siberian Husky" and "wolf dog" instead of true wolves. I:
1. Visually confirmed the misidentifications by looking at the source images
2. Replaced the underlying image files with correct wolf photos
3. Deleted the stale DB rows
4. Re-ran ingestion to re-tag with the corrected images

This is the kind of human verification loop the system is designed to
support — the confidence scores were high (0.95) even for misidentifications,
which is exactly why the mismatch guard (Phase 3) needs category + similarity
checks, not just confidence.
